# TABETUNAGU v2 PoC 公開チェックリスト

production で `ENABLE_V2_CHECKOUT=true` にする前に、このチェックリストをすべて満たしてください。
状態の表記: **DONE**（確認済み）/ **BLOCKED**（公開前に対応が必要）/ **HUMAN CHECK**（人の確認が必要・未実施）/ **NOT REQUIRED**（PoC には不要）。
コードのテスト・Playwright だけで確認したものは「コードで確認」と書き、実機・実決済の確認とは区別します。

- production で `ENABLE_V2_CHECKOUT=true` にしても、`STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` /
  `STRIPE_CHECKOUT_RETURN_URL`（https）/ `CRON_SECRET`（16文字以上）のどれかが欠けていれば、v2 は自動的に OFF（旧導線）のままになります。
- 設定の状態（秘密鍵の有無・定期処理の最終実行・売上受取設定が未完了の店舗数・要確認の決済）は、管理画面トップの「技術状態・PoC 公開準備」で確認できます（値そのものは表示しません）。

| 返金の失敗 / 要確認の決済（requires_review） | 管理画面「要確認の決済」「失敗した返金」 | Stripe ダッシュボードで状態を確認し、必要なら手動で返金。お客様に連絡 | 運営 |
| 店舗の売上受取設定が未完了 | 管理画面「売上受取設定が未完了の稼働店舗」 | 店舗に「売上受取設定」の再開を案内（未完了の店舗の商品は購入できない） | 運営 |
| 店舗モニターが更新されない | モニターの「最終更新」・接続エラー表示 | 店舗に再読み込みを案内。受取チケットの目視確認で受け渡しは続けられる | 運営 |
| DB 接続の障害 | 画面のエラー・Vercel のログ | Supabase のステータスを確認。長引く場合は `ENABLE_V2_CHECKOUT=false`（新しい決済を止める） | 開発 |
| LINE Push が unauthorized（401） | 管理画面「LINE日次通知」「LINE注目商品デモ」の記録（unauthorized） | チャネルアクセストークンを再発行して Vercel に設定。日次通知は `ENABLE_LINE_DIGEST_SEND=false` で停止 | 開発 |
| 不正・紛争 | Stripe のメール通知 | Stripe ダッシュボードで期限内に対応 | 運営 |

## ロールバック

最優先: **`ENABLE_V2_CHECKOUT=false`（または削除）にして再デプロイ** → 旧フロー（予約 → 店頭 QR → お店で支払い）に戻る。すでに決済済みの v2 注文の受取チケット・スワイプ・返金・Webhook はそのまま動く。

| 止めたいもの | 方法 |
|---|---|
| v2 の新しい決済 | `ENABLE_V2_CHECKOUT=false` → 再デプロイ |
| LINE 日次通知の送信 | `ENABLE_LINE_DIGEST_SEND=false`（定期実行は `ENABLE_LINE_DIGEST_CRON=false`）→ 再デプロイ |
| LINE 注目商品デモ | `ENABLE_LINE_MARKETING_DEMO=false` → 再デプロイ |
| コードの不具合 | Vercel の Deployments で直前のデプロイに Promote（Instant Rollback）。DB のマイグレーションは追加のみのため、古いコードでもそのまま動く |

### 公開前に確認が必要な事項（ブロッカー候補）

コードの変更はしていない。公開前に運営が LINE の最新の規約・ガイドラインで確認する。

- [ ] **LINE ミニアプリでの外部決済（Stripe Checkout）**: LINE Developers「Handling payments」では、アプリ内課金（App Store / Google Play、デジタルコンテンツのみ）以外の決済は通常の Web と同様に実装でき、
      **外部ドメインでの決済完了後に LINE ミニアプリのページへ戻るよう設計すること**とされている。TABETUNAGU は実店舗で受け取る食品（物理的な商品）の事前決済で、
      Checkout の戻り先（`STRIPE_CHECKOUT_RETURN_URL`）を `https://miniapp.line.me/<LIFF ID>` にすればこの設計に沿う。審査前に「LINE ミニアプリ ポリシー」「開発ガイドライン」の最新版で、
      物理商品の外部決済・審査上の追加要件がないことを確認する（この環境からは規約本文を取得できず未確認）。
- [ ] **認証済みミニアプリの審査**: 外部ブラウザでも LINE を使わない人が閲覧できること（現状: 商品閲覧はログイン不要、購入時のみ LINE ログイン）が審査上問題ないか。
- [ ] 店舗 QR（旧フロー・障害時用）の URL は `https://liff.line.me/<LIFF ID>/c/...` の形式で発行している（旧形式でも開ける）。発行し直す場合は miniapp.line.me へ切り替えるか判断する。

## 障害時のフォールバック（旧 QR フロー）

旧フロー（予約 → 店頭 QR → お店で支払い）のコード・画面・関数は PoC の保険として残しています。通常の画面からは隠れています。

- **自動では切り替わりません。** 運営が判断して切り替えます。
- 切り替え: production の環境変数 `ENABLE_V2_CHECKOUT` を `false`（または削除）にして再デプロイ。
  - 商品詳細の「食べつなぐ」は予約確認（旧導線）、ナビは「予約」「QR」に戻ります。
  - すでに決済済みの v2 注文は、受取チケット・スワイプ・返金・Webhook がそのまま動きます。
- 事前準備: 各店舗の店頭 QR（店舗画面「QRコード」）を印刷しておく。旧フローではお客様が店頭 QR を読み取って完了します。
- 店舗への連絡: 切り替えたことと、お会計が店頭（レジ）に戻ることを伝える。

## PoC 指標の定義

管理画面トップ「PoC 指標」。定義は `src/server/services/v2-metrics.ts`（`getV2Kpis`）と一致しています。

| 指標 | 定義 |
|---|---|
| 食べつなぎ率 | 期間内に受取開始の出品について、売れた数量（v2 の決済済み注文 + 旧フローの成約）÷ 出品数量 |
| 30日リピート率（v2） | 初回の決済済み注文から30日以上経ったユーザーのうち、初回から30日以内に2回目の決済済み注文があった割合 |
| 店舗 WAU | 直近7日に受取開始の出品があった稼働店舗の数（代わりの指標。店舗のログイン状況による WAU は未対応） |
| 自己スワイプ完了率 | 受取期限（受取終了 + 猶予15分）が到来した決済済み注文のうち、受取完了（picked_up）の割合 = picked_up ÷（picked_up + unclaimed + 期限を過ぎて未処理の paid） |
| STANDARD 移行候補 | FREE 店舗のうち、直近30日の v2 売上（商品小計）が損益分岐 41,500円以上 |

売上の基準（v2）: 決済済み（paid / picked_up / unclaimed）を決済日時で計上。返金済み・決済待ちは含めない。旧フローの成約とは別に集計し、二重計上しない。

## PoC 結果の書き出し

管理画面トップ「PoC 公開準備」の CSV リンク（管理者のみ）:
- 注文（`/admin/export?type=orders&period=month|30d|all`）: 注文番号・店舗・状態・金額・各時刻
- 店舗別（`/admin/export?type=stores&period=...`）: 決済済み件数・GMV・受取完了・未受取・返金・プラットフォーム売上

個人情報（ユーザー ID・表示名・IP など）は含めません。
