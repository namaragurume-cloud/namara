# プライバシー設計（PRIVACY_DESIGN）

## 1. データの分離

| 区分 | 例 | 誰が見られるか |
| --- | --- | --- |
| 利用者本人に関する情報 | LINE識別子（HMAC化）、検索文、行動ログ、同意記録 | サーバーと運営のみ |
| 店舗向け統計 | エリア×ジャンル等の検索回数（匿名集計） | 店舗（自店エリア／契約プランの範囲） |
| 店舗自身の数値 | 自店の表示回数・クリック数 | その店舗 |

店舗には **生の検索文・セッションID・個人の操作履歴を一切渡しません**（自動テストで確認）。

## 2. 匿名集計の再識別対策（`src/lib/analytics/aggregate.ts`）
- **少数セル抑制**：ユニーク利用者数が 5 人未満の区分は件数を出さない（「少数のため非表示」）
- **1人が何度検索しても1人**として数える（ヘビーユーザーで閾値を超えないように）
- **丸め**：件数を5単位に丸め、差分から少数セルを逆算しにくくする
- 抑制した区分をまとめた「その他」も、まとめて5人未満なら出さない
- 全体で20人未満のときは「分析に必要なデータが不足しています」
- DB 側でも `store_demand_by_genre()` が同じ抑制をかける（店舗はログを直接読めない）

## 3. 識別子の保護
- LINE の userId は保存せず、`HMAC-SHA256(IDENTITY_HASH_SECRET, "line:"+userId)` の値だけを使う
- Web は Cookie のランダムID（氏名・メールは扱わない）
- ログに個人を特定できる値（userId、検索本文）を出さない

## 4. 保存期間（案）

| データ | 期間 |
| --- | --- |
| 検索文（生テキスト） | 90日（以後 NULL。集計用の条件のみ残す） |
| 行動ログ | 13か月（前年同月比較のため） |
| 匿名集計値 | 無期限（個人に戻せないため） |
| 広告の課金記録 | 会計上必要な期間（税務の要件を確認して決定） |

## 5. 同意
- LINE：友だち追加時のあいさつで利用目的とプライバシーポリシーへのリンクを提示し、`consent_records` に規約バージョンを記録（Phase 7）
- Web：検索欄の下に利用目的を表示（実装済み）
- 匿名統計への利用は利用規約・プライバシーポリシーに明記（草案：`/privacy`, `/terms`）

## 6. 削除対応
- 利用者からの依頼で、本人の識別子・同意・行動ログを削除し、検索条件は本人と切り離す（`deleteConsumerData` / `delete_consumer_data`）
- LINE のブロック・削除依頼の受付窓口は Phase 7 で用意

## 7. 公開前の確認事項（要専門家）
- 個人情報保護法上の「個人関連情報」「仮名加工情報」等の該当性と、第三者提供（店舗への統計提供）の整理
- プライバシーポリシー・利用規約の確定
- 電気通信事業法の外部送信規律（Cookie 等）への対応要否
