## 次にやること（Phase 2 の詳細計画）
1. 🔒 Supabase プロジェクト作成（オーナー作業。東京リージョン・プラン確認）
2. マイグレーション適用（まずは開発用プロジェクト。本番とは分ける）
3. `src/lib/server/db.ts` の代わりに Supabase 版リポジトリを実装（サービス層の関数名・認可はそのまま）
4. Supabase Auth（メールのマジックリンク）で店舗ユーザー・運営ログイン。デモログインは開発環境だけに残す
5. 運営画面に店舗の追加・編集フォーム（Zod 検証・store_sources 記録・重複チェック）
6. 架空サンプル店舗の投入スクリプト（本番プロジェクトには投入しない）
7. 検索ログ・イベントの DB 保存、pg_cron で保存期間の削除
8. レート制限を DB ベースに変更（複数サーバーで有効にするため）
9. pgTAP（`supabase test db`）へ RLS テストを移行、CI（GitHub Actions）で lint/test/build を自動化

## Phase 3 以降の主な論点
- 実在店舗 100〜200 店の情報収集と確認方法（店舗への許諾、価格の根拠、写真の利用許可）
- OpenAI のコスト上限と、辞書解析で十分なケースの切り分け
- LINE の返信期限内に処理できない場合のキュー設計（Push API は通数課金）
- 広告の課金方式（月額固定 or クリック課金）の決定
