# MIRATSUMU（ミラツム）公式サイト

北海道発のクリエイターキャスティングサービス「MIRATSUMU（ミラツム）」の公式サイトです。運営メディアは「なまらグルメ」です。

- Next.js 16（App Router）/ React 19 / TypeScript
- Tailwind CSS v4 / Motion / Lucide Icons / Zod
- Vercel へのデプロイを想定（CMS なし。内容は `src/data/` のファイルで管理）

> 以前の静的 HTML 版（`index.html` / `privacy.html` / `css/` / `js/`）はこの Next.js 版に置き換えました。過去の内容は Git の履歴から参照できます。

---

## 1. ローカルで起動する

必要なもの：Node.js 20.9 以上（推奨 22）

```bash
npm install
cp .env.example .env.local   # 必要に応じて値を設定
npm run dev                  # http://localhost:3000
```

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー |
| `npm run build` | 本番ビルド |
| `npm run start` | 本番ビルドの起動 |
| `npm run lint` | ESLint |
| `npm run typecheck` | 型チェック |

ローカルでフォームを試すときは `.env.local` に `MAIL_PROVIDER=console` を設定すると、送信内容がターミナルに表示されます（メールは送信されません。本番では無効）。

---

## 2. Vercel で公開する

1. GitHub のこのリポジトリを Vercel にインポート（Framework は自動で Next.js になります）
2. Project Settings → Environment Variables に「3. 環境変数」の値を設定
3. Deploy
4. 独自ドメインを決めたら Vercel の Domains で設定し、`NEXT_PUBLIC_SITE_URL` をそのドメインに変更して再デプロイ

---

## 3. 環境変数

`.env.example` に一覧があります。秘密情報（API キー）は `.env.local` か Vercel の設定画面にのみ保存し、Git にコミットしないでください。

| 変数 | 必須 | 内容 |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | ○ | 公開 URL（canonical / OGP / sitemap に使用） |
| `MAIL_PROVIDER` | ○ | `resend` / `formspree` / `console`（開発用） |
| `MAIL_TO` | resend 時 | 通知先（既定 `namaragurume@gmail.com`）。カンマ区切りで複数可 |
| `RESEND_API_KEY` | resend 時 | Resend の API キー |
| `MAIL_FROM` | resend 時 | 送信元（Resend で認証済みのドメインのアドレス） |
| `FORMSPREE_CONTACT_FORM_ID` | formspree 時 | 企業問い合わせ用フォーム ID |
| `FORMSPREE_PARTNER_FORM_ID` | 任意 | 発信者登録用フォーム ID（空なら企業問い合わせ用と共用） |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` | 任意（推奨） | Cloudflare Turnstile（Bot 対策） |
| `NEXT_PUBLIC_GA_ID` | 任意 | Google Analytics 4 の測定 ID |
| `INSTAGRAM_BUSINESS_ACCOUNT_ID` / `INSTAGRAM_ACCESS_TOKEN` | 任意 | Instagram フォロワー数の自動取得（下記参照） |
| `CONTENT_PREVIEW` | 任意 | `true` で非公開の実績・発信者をプレビュー表示（ローカル／Vercel プレビュー環境のみ有効） |

## 4. フォーム通知の設定

フォームは `/api/contact`・`/api/partner`（サーバー側）で入力内容を検証し、メールで通知します。**送信設定が未完了の場合、フォームには「送信設定を準備中」と表示され、送信ボタンは押せません。** 成功画面はサーバーで送信に成功した場合のみ表示されます。

件名：
- 企業問い合わせ：`【企業問い合わせ】MIRATSUMU`
- 発信者登録：`【発信者登録申請】MIRATSUMU`

返信先（Reply-To）には送信者のメールアドレスが入るため、通知メールにそのまま返信できます。

### A. Resend を使う（推奨）
1. https://resend.com でアカウントを作成
2. 送信元にするドメイン（独自ドメイン）を追加し、DNS レコード（SPF / DKIM）を設定して認証
3. API キーを発行
4. 環境変数を設定：`MAIL_PROVIDER=resend` / `RESEND_API_KEY` / `MAIL_FROM="なまらグルメ <noreply@独自ドメイン>"` / `MAIL_TO=namaragurume@gmail.com`

### B. Formspree を使う（ドメイン未決定の間の暫定案）
1. https://formspree.io でフォームを作成し、通知先を `namaragurume@gmail.com` に設定（旧サイトのフォーム ID `xppqller` も使えます）
2. 環境変数を設定：`MAIL_PROVIDER=formspree` / `FORMSPREE_CONTACT_FORM_ID`
   - 発信者登録を別のフォームで受けたい場合のみ `FORMSPREE_PARTNER_FORM_ID` も設定（空なら同じフォームに届き、件名で区別）

### スパム対策
- ハニーポット（人には見えない入力欄）
- 表示から 3 秒未満の送信を破棄
- 同一 IP からの送信回数の制限（10 分あたり 5 回）
- 別サイトからの送信（Origin 不一致）の拒否
- Cloudflare Turnstile（環境変数を設定すると有効）

※レート制限はサーバーのメモリ上で行うため、Vercel ではインスタンスごとの制限になります。厳密に制限したい場合は Upstash Redis などに置き換えてください（`src/lib/spam.ts`）。

**公開前に必ず本番環境で両フォームの送信テストを行い、`namaragurume@gmail.com` に届くこと（迷惑メールフォルダも）を確認してください。**

## 5. 内容の変更方法

サイトの文章・数値はほぼすべて `src/data/` にあります。

| ファイル | 内容 |
|---|---|
| `brand.ts` | MIRATSUMU のブランドコンセプト・スローガン・ブランドストーリー・ロゴの意味 |
| `site.ts` | サイト名・会社情報・Instagram・トップの数値（数字で見る「MIRATSUMU」）・なまらグルメのフォロワー数・メニュー |
| `images.ts` | サイト内の写真の差し替え（トップ最上部の背景写真 `heroMosaic` を含む） |
| `activities.ts` | これまでの活動（現場取材・イベント・企業との取り組み）と写真 |
| `services.ts` | サービス内容・対応 SNS |
| `reasons.ts` | 選ばれる5つの理由 |
| `creators.ts` | 掲載するインフルエンサー |
| `cases.ts` | PR実績 |
| `pricing.ts` | 料金・プラン |
| `faq.ts` | よくある質問 |
| `flow.ts` | ご利用の流れ |
| `history.ts` | 活動年表 |
| `privacy.ts` | プライバシーポリシーの確定状態・制定日 |

### 画像を変更する
1. 画像を `public/images/` 以下に置く（例：`public/images/food/hero.jpg`）
   - フォルダ：`brand/`（ロゴ）・`food/`・`creators/`・`works/`・`about/`
   - 推奨：横 2000px 程度までの JPG / WebP（自動で最適化されます）
2. `src/data/images.ts` の該当項目の `src` にパスを記入し、`alt` を実際の内容に合わせる

ロゴは `public/images/brand/` の `miratsumu-*.png`（`-white` は暗い背景用）。同じファイル名で上書きすれば差し替わります。ファビコンは `src/app/icon.png`。

`src` が空の項目は「仮素材」と表示されたプレースホルダーになります。

### インフルエンサーを追加する
`src/data/creators.ts` の `creators` 配列に追加します。

```ts
{
  id: "taro",                       // 半角英数字
  account: "taro_gourmet",          // @なし
  name: "たろう",                    // 任意
  image: "/images/creators/taro.jpg",
  platform: "Instagram",
  profileUrl: "https://www.instagram.com/taro_gourmet/",
  followers: 32000,
  followersAsOf: "2026年10月",
  genres: ["ラーメン", "居酒屋"],
  areas: ["札幌"],
  examples: [{ title: "〇〇の紹介リール", url: "https://www.instagram.com/reel/..." }],
  published: true,                  // 本人の掲載許可を得てから true
},
```

- **本人から名前・写真・投稿事例の掲載許可を得たものだけ `published: true` にしてください。**
- 掲載が 0 人の間は、一覧の代わりに「最適なグルメインフルエンサーをご提案します」という案内を表示します。
- 6 人以上になると、一覧ページにエリア・ジャンル・フォロワー規模の絞り込みが自動で表示されます（`src/components/sections/CreatorList.tsx` の `FILTER_THRESHOLD`）。
- カードの「この発信者を含めて相談する」を押すと、お問い合わせフォームの「希望インフルエンサー」に自動入力されます。

### 実績を追加・公開する
`src/data/cases.ts` に事例があります（現在 3 件、すべて `published: false`）。`【要確認】` の箇所を確認済みの事実に書き換え、以下がすべて揃ったら `published: true` にしてください。

- 実績値と集計期間・比較方法
- クライアントの公開許可（匿名掲載を含む）
- PR との関係（他の施策の有無）
- 画像・動画の掲載許可

公開した事例は `/works/[slug]` に詳細ページが自動で作られ、サイトマップにも追加されます。成果を PR だけの効果と断定する表現は避けてください。

### 料金を変更する
`src/data/pricing.ts` を編集します。`price` が空欄のプランは「個別見積もり」と表示されます。**確定していない金額は入力しないでください。** 税込・税別が決まったら `taxNote` に記入してください。

### 非公開コンテンツを確認する
`.env.local` に `CONTENT_PREVIEW=true` を設定して `npm run dev` すると、`published: false` の実績・発信者が「非公開プレビュー」の表示付きで確認できます。本番環境では無効です。

### フォロワー数の自動取得（Instagram Graph API）

> 現在は `src/data/site.ts` の `showFollowerCounts` が `true` で、発信者カード（小さいカード含む）と /about にフォロワー数を表示しています。非表示に戻す場合は `false` にしてください。

トップの「Instagramフォロワー」と、発信者カードのフォロワー数を Instagram から自動取得できます（6時間ごとに更新。`src/lib/instagram.ts`）。設定しない場合は `src/data/` に入力した数値を表示します。

- 取得できるのは **プロアカウント（ビジネス／クリエイター）** のみです。個人アカウントの発信者は手入力の数値（`followers`）が表示されます。未入力なら非表示。
- Instagram の規約上、ページの読み取り（スクレイピング）は行わず、公式 API を使います。

設定手順（なまらグルメのアカウントで1回だけ行います）：

1. なまらグルメの Instagram をプロアカウントにし、Facebook ページと連携する
2. [Meta for Developers](https://developers.facebook.com/) でアプリを作成し、「Instagram Graph API（Facebook ログイン経由）」を追加
3. グラフAPIエクスプローラで `instagram_basic` と `pages_show_list`（必要に応じて `business_management`）の権限付きトークンを取得し、長期トークン（またはページのトークン）に交換
4. `GET /me/accounts?fields=instagram_business_account` で Instagram ビジネスアカウント ID を確認
5. Vercel の環境変数に `INSTAGRAM_BUSINESS_ACCOUNT_ID` と `INSTAGRAM_ACCESS_TOKEN` を設定して再デプロイ

※ 長期ユーザートークンの有効期限は約60日です。期限切れになると自動で手入力の数値に戻ります（表示は崩れません）。期限のないページトークンの利用を推奨します。

## 6. アクセス解析

`src/lib/analytics.ts` の `track()` で以下のイベントを送信します（計測タグが読み込まれている場合のみ）。

| イベント | タイミング |
|---|---|
| `generate_lead` | 企業問い合わせの送信成功（最重要 KPI） |
| `partner_apply` | 発信者登録申請の送信成功 |
| `cta_click` | CTA ボタンのクリック（`location` で設置場所を識別） |
| `instagram_click` | Instagram / DM への遷移 |

`NEXT_PUBLIC_GA_ID` を設定すると GA4 が読み込まれます。Cookie 同意バナーの要否・利用サービスは公開前に決定し、必要に応じて `src/components/layout/Analytics.tsx` を変更してください。

## 7. ディレクトリ構成

```text
src/
  app/(site)/          公開サイトの各ページ（URL = フォルダ名）
  app/(ops)/           キャスティング管理ツール（/admin・/m・/p）
  app/api/             API（contact, partner, cron, line）
  app/                 sitemap/robots/OGP
  components/
    layout/            Header / Footer / Analytics
    sections/          トップページの各セクション・共通セクション
    ui/                ボタン・カード・見出し・アコーディオンなどの部品
    forms/             お問い合わせ・登録フォーム
    animation/         スクロール表示・カウントアップ
  data/                サイトの内容（ここを編集）
  lib/                 入力検証・メール送信・スパム対策・計測
  lib/ops/             管理ツールのデータ保存・LINE/メール送信・集計・レポート
public/images/         画像
```

URL を変更する場合は `src/app/(site)/` のフォルダ名を変更し、`src/data/site.ts` のメニューと `src/app/sitemap.ts` を合わせて修正してください。

## 9. キャスティング管理ツール（/admin）

PR依頼から日程調整・飲食店への共有・インサイト回収・レポート作成までを1か所で行う業務ツールです。公開サイトとは別の画面で、検索エンジンにも載りません。

### 流れ
| | やること | 誰が |
|---|---|---|
| 1 | 案件（店舗・PR内容・報酬・撮影候補日・投稿日（カレンダーで複数選択）・回答期限）を作成し、発信者を選んで**一括送信** | あなた |
| 2 | 発信者が専用ページで参加可否・参加できる撮影日時・投稿日（案件の投稿日からカレンダーで選択）を回答 | 発信者 |
| – | 回答期限の前日に未回答者へ自動リマインド | 自動 |
| 3 | 回答を自動集計し、撮影枠（人数上限つき）を自動で割り当て。確認して「確定」→ 発信者に撮影日時・住所・投稿条件が届く | 自動＋あなたが確認 |
| 4 | 飲食店へ撮影日・投稿予定日を共有（メール送信 or 文面コピー） | あなた |
| – | 撮影前日に発信者へリマインド | 自動 |
| 5 | 月末に、投稿予定日を過ぎた人へインサイトのスクショ提出のお願い（撮る画面の案内つき） | 自動 |
| 6 | 発信者がスクショを**公式LINEに送る**か専用ページから送る → AIが数値を読み取り、必要な項目が写っていなければ「〇〇が写っていません」と本人に自動連絡。そろうまで3日後に1回リマインド | 自動 |
| 7 | 集まった数値から16:9のスライド形式のレポートを自動作成（表紙KPI・投稿別・属性・媒体別・考察／提案、PDF保存・CSV）。文章はAIで下書きして修正 → 飲食店へ送付 | 自動＋あなたが確認・送付 |

### 飲食店への提案（料金表）
1. 発信者ごとの料金（1投稿・税別）・アイコン画像・SNSのURL（空欄ならSNSとアカウントから自動）を、各発信者のページで設定しておく。フォロワー数は、ホームページ（/creators）と同じアカウント名の発信者ならホームページの数値（Instagram APIの自動取得、または `src/data/creators.ts` の入力値）と連動します（毎朝・発信者の保存時・料金表の作成時。「発信者」の「ホームページからフォロワー数を取り込む」でも可）。消費税率・ディレクション費など固定費・有効期限・料金の備考は「設定 → 飲食店への提案」
2. 「提案」でお店と発信者を選び「料金表をつくる」→ 設定した料金から明細・小計・消費税・合計を自動で計算（人数を絞ったプランBも追加可）
3. お店の公式LINE（グループ）・メール・コピーでURLを送付。お店は料金表を見て、PDFで保存できます
4. 決まったら「この提案で案件をつくる」→ 選んだ発信者にチェックが入った状態で依頼に進めます

※ 料金が未設定の発信者は料金表で0円になるため、警告が出ます。

### 撮影日時の決め方（案件ごと）
- **候補日を決める**：撮影できる日時が限られているとき。発信者は候補の中から参加できる日時をすべて選びます
- **期間と時間帯から選んでもらう**：幅広く調整できるとき。期間・曜日・時間帯・1回の撮影の長さ・開始時刻の刻み・同じ時間の人数（同伴者込み）・撮影できない日を設定すると、発信者が第1〜第3希望（日付＋開始時刻）を選びます。自動の割り当ては希望の順番どおりに、人数の上限を守って入れます

### 撮影日の変更・再調整
- **撮影候補日の中で日時を変える**：案件ページの割り当て表で日時を変えて「確定して発信者に連絡」→ 変えた人にだけ「日程変更（変更前 → 変更後）」の連絡が届く
- **発信者に選び直してもらう**：「お店の都合などで、発信者に日程を選び直してもらう（再調整）」から理由を添えて依頼 → その人の回答画面が再び開き「日程の再調整のお願い」が届く → 選び直した結果を確定すると「日程変更」の連絡が届く（お店の希望日時が候補日にない場合は、先に候補日を追加）
- お店に共有したあとに変更・再調整があると、案件ページとホームに「お店に再共有」と表示されます

### 投稿前の動画チェック（案件ごとに設定）
案件ページの「投稿前の動画チェック」で、なし／A：発信者 → お店が確認／B：発信者 → あなたが確認 → お店が確認 を選べます。
1. 撮影日の翌日、発信者に「動画を送ってください」と自動で届く
2. 発信者が投稿ごとのページから動画をアップロード
3. （Bのみ）あなたが管理画面の依頼詳細でOK／修正（修正内容は発信者へ自動連絡）
4. お店に確認のお願いが届き（公式LINE連携済みならLINE、未連携なら管理画面の「お店にLINEで送る」から）、お店は飲食店用ページで「OK」か「修正をお願いしたい」を押す
5. 結果は発信者へ自動連絡（OKなら投稿日に投稿、修正なら出し直し）。お店の確認が2日止まると1回リマインド

お店からLINEで返事が来た場合は、依頼詳細の「代理で入力」から記録できます。動画は投稿が確認できたら（または投稿日の7日後に）自動で削除されます。
**動画の保存には Vercel Blob が必要です**（Storage → Blob を追加し Production に接続）。新しい接続方式（OIDC。`BLOB_STORE_ID` と `BLOB_WEBHOOK_PUBLIC_KEY` が入る）と以前の方式（`BLOB_READ_WRITE_TOKEN`）のどちらにも対応しています。Blob の置き場を「Private」で作った場合は、環境変数 `VIDEO_BLOB_ACCESS=private` を設定してください（表示のたびに6時間有効のURLを作ります）。

### 飲食店の公式LINE連携
飲食店も発信者と同じく、連携コードを公式LINEに送ると紐づきます（飲食店ページの「案内文をコピー」）。連携済みの店には、撮影日程の共有・動画の確認依頼・レポート送付がLINEで自動で届きます。

**お店の複数の方で確認する場合**は、お店のLINEグループに公式LINEを招待し、そのグループで連携コードを送ってもらいます。以後の連絡はグループに届きます（個人の連携より優先）。グループ内の普段の会話には反応しません。公式LINEがグループから外されると連携も外れます。
事前に LINE Official Account Manager の設定で「グループ・複数人トークへの参加を許可する」をオンにしてください。グループへの送信は、メンバー数分の通数として数えられる場合があります。

動画を確認したお店の方は、「確認した方のお名前（任意）」を入力できます。

### 集めるインサイト項目
| 媒体 | 必須（写っていなければ本人に連絡） | あれば使う |
|---|---|---|
| Instagram | 閲覧数・閲覧者・平均再生時間（動画のみ）・フォロー数・閲覧数の上位のソース・フォロワー以外の割合・年齢・性別 | いいね・コメント・シェア・保存 |
| TikTok | 総視聴数・いいね・コメント・シェア・保存・新しい視聴者の割合・非フォロワーの割合・性別・年齢 | 平均視聴時間 |

項目と撮り方の案内は `src/lib/ops/insight-fields.ts` で変更できます。スクショ画像は180日で自動削除されます（読み取った数値は残ります）。
LINEで画像を受け取ったとき、その発信者にインサイトをお願いしている投稿が複数あると自動では振り分けられないため、専用ページから投稿ごとに送るよう返信します。

- **進捗は自動で判定**（回答 → 撮影 → 投稿 → インサイト → 完了）。発信者は「投稿しました」などの報告をする必要はありません（投稿日を過ぎるか、スクショが届いた時点で投稿済みになります）。発信者のページには「いまやること」と月ごとの依頼一覧、管理画面には「月別の進捗」（発信者ごと・対応待ちの絞り込み）があります。
- 発信者への連絡は **公式LINE（連携済みの人）→ メール** の順に自動送信します。どちらも使えない人は「自動送信できなかった人」として表示され、文面コピー・「LINEで送る」から手動で送れます（送れていないのに送信済みとは表示しません）。
- DMや電話で返事が来た場合は、案件ページの「詳細・代理入力」から回答やインサイトを入力できます。
- 送ったメッセージはすべて「送信履歴」に残ります。
- メッセージの文面は、管理画面の **設定 → メッセージの文面** から編集できます（保存するとすぐ反映。{発信者名} などの差し込み項目が使えます。「初期の文面に戻す」も可）。初期の文面は `src/data/ops-templates.ts` にあります。

### 実施済みの案件のレポートを作る
すでに撮影・投稿が終わったPRも、レポートだけ作れます。
1. 案件をつくる（撮影日・投稿日は過去の日付でOK）
2. 案件ページの「実施済みの案件として記録する（発信者に連絡しない）」で発信者を選んで記録（LINE・メールは送られません）。投稿日を空欄にすると、各発信者が提出ページで投稿した日を入力します（提出のお願いにもその案内が入ります）
3. 各発信者の「詳細・代理入力」からスクショを追加する（DMで受け取ったものなど）か、「今すぐ提出をお願いする」で本人に依頼
4. そろったらレポートを確認して送付

### URL
| URL | 使う人 |
|---|---|
| `/admin` | あなた（パスワードでログイン） |
| `/m/<発信者ごとのランダムURL>` | 発信者（依頼の一覧・回答・インサイト入力） |
| `/p/<案件ごとのランダムURL>` | 飲食店（撮影日程・レポート。共有／送付済みにしたものだけ表示） |

### 初期設定（Vercel）
1. **データ保存先**：Vercel のプロジェクト → Storage → Marketplace から **Upstash Redis** を追加してプロジェクトに接続（無料枠で足ります）
2. 環境変数 `ADMIN_PASSWORD`（8文字以上）・`ADMIN_SESSION_SECRET`（ランダムな長い文字列）・`CRON_SECRET`（ランダムな文字列）を設定
3. **公式LINE**（推奨）：[LINE Developers](https://developers.line.biz/) で公式アカウントの Messaging API チャネルを作成し、
   - `LINE_CHANNEL_ACCESS_TOKEN`（長期）・`LINE_CHANNEL_SECRET`・`LINE_BOT_BASIC_ID`（@から始まるID）を設定
   - Webhook URL を `https://<ドメイン>/api/line/webhook` にして「Webhookの利用」をオン
   - LINE Official Account Manager の応答設定で「応答メッセージ」をオフ（自動返信がツールの返信と重ならないように）
   - 無料プランは月200通までです。発信者が多い場合はライトプラン以上を検討してください
4. **メール**（LINE未連携の発信者・飲食店への送付）：フォームと同じ Resend の設定（`MAIL_PROVIDER=resend`・`RESEND_API_KEY`・`MAIL_FROM`）を使います。返信先は `MAIL_TO` の1件目です
5. **動画の保存先**（動画チェックを使う場合）：Storage → **Blob** を追加して Production に接続（`BLOB_STORE_ID` か `BLOB_READ_WRITE_TOKEN` が自動で入ります。Private の置き場なら `VIDEO_BLOB_ACCESS=private`）
6. **スクショの自動読み取り**（推奨）：[Anthropic Console](https://console.anthropic.com) で API キーを発行し `ANTHROPIC_API_KEY` に設定（1投稿の読み取りで数円程度）。未設定でもスクショは受け取れ、数値は管理画面で手入力できます
7. 再デプロイ後、`/admin/settings` で各連携が「設定済み」になっていることを確認

毎日の自動処理は `vercel.json` の `crons` で毎日10時ごろ（日本時間）に `/api/cron/daily` を呼び出します。インサイト依頼の日は `OPS_INSIGHT_DAY`（`last`＝月末、または日にち）で変更できます。

### 発信者の登録とLINE連携
1. 「発信者」で登録（1人ずつ、またはスプレッドシートから貼り付けてまとめて登録）
2. 発信者ページの「最初の案内文」をコピーしてDMで1回送る（連携コード・連携ボタン・専用ページURL入り）
3. 発信者が公式LINEに連携コードを送ると自動で紐づき、以降の連絡はすべてLINEで自動送信されます

### デモ（サンプルデータで画面を試す）
Vercel の**プレビュー環境**（main 以外のブランチをプッシュすると自動で作られるURL）では、データの保存先（Redis）を設定していなければ自動でデモになります。`/admin` を開き、パスワード `demo1234` でログインしてください。

- 店舗・発信者・数値はすべて架空のサンプルです。LINE・メールは実際には送信されず、送信履歴に記録されるだけです
- スクショを送ると、画像は読み取らずにサンプルの数値が入ります（1枚だと「年齢・性別が足りない」例、2枚以上でそろう例）
- 変更はメモリ上だけなので、しばらくすると元に戻ります（設定ページの「サンプルデータに戻す」でも戻せます）
- ローカルでは `OPS_DEMO=true npm run dev` でデモになります
- **本番環境（Production）では、設定に関わらずデモにはなりません**

### ローカルで試す
`.env.local` に `ADMIN_PASSWORD=` と `MAIL_PROVIDER=console` を設定して `npm run dev` → http://localhost:3000/admin 。データは `.data/ops.json`（Git 管理外）に保存され、メールはターミナルに表示されます。
